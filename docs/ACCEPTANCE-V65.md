# V65 验收记录

日期：2026-06-08

## 目标

继续加固订单、库存和客户存酒之间的账务边界：订单商品已经转成客户存酒后，不能再直接普通退款，避免库存恢复与客户存酒权益同时存在。

## 已完成

- 新增订单是否存在 `from_order` 客户存酒流水的判断。
- `/api/admin/orders/:orderId/refund` 在发现订单已转存客户存酒时返回 409。
- 错误提示明确要求先人工处理存酒后再退款。
- 后端自验收改为两单场景：
  - 已转存客户存酒的订单退款被拦截。
  - 未转存订单仍可正常退款、恢复库存并扣回对应积分。

## 剩余风险

- 当前策略是先拦截并要求人工处理存酒；后续如门店需要，可增加“退款并同步冲销未取存酒”的受控流程。
- 真实微信退款场景同样会在申请退款前被拦截，需在运营流程中培训管理员先处理存酒。
