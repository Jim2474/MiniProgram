## 审计口径

- `完成`：已有后端接口、小程序入口和自动验收覆盖。
- `收敛`：Excel 原始项存在，但用户后续明确“先不做/暂不做”，当前已隐藏或禁用，后端也拒绝误用入口。
- `生产待接入`：本地业务闭环或接入点已完成，但上线前仍依赖真实微信配置、商户配置、部署策略或人工真机回归。

## 生产前重点

- 配置真实微信小程序登录、手机号授权、JSAPI 支付、支付回调证书和真实退款。
- 配置真实小程序码生成；当前已支持 dry-run 和 payload 二维码，生产仍依赖微信接口配置。
- 当前 `/api/health` 已提供 `productionReady` 与 `productionBlockers`，上线前应以该接口和真机回归共同作为发布门槛。
- 选择正式数据部署策略：当前支持 JSON Store 和单节点 SQLite，生产需明确备份、迁移、监控和权限策略。
- 做微信开发者工具和真机完整回归，覆盖扫码、支付、退款、地图、电话、二维码图片和表单交互。

## 当前结论

按用户后续明确收敛的范围，Excel 中属于当前产品的核心功能已覆盖：员工专属二维码归属、微信支付链路地基、消费积分、后台手动积分、客户侧积分显示开关、完整单店 SKU 库存、两套账、存酒有效期人工处理、轻量预约、员工业绩提成、后台人员管理、人员岗位边界、咖位类型配置、完整升盲标题配置、财务营业明细、支付明细脱敏和荷官升盲。剩余主要是生产微信配置、数据部署策略和微信开发者工具/真机回归；这些不应仅凭代码测试判定完成。
